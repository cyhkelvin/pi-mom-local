# search

> **2026-09-15：`search` 已經是內建工具了。**
> 這份文件保留下來當實作說明與備援（bash 路徑仍然可用），
> 但正常情況下直接呼叫 `search` 工具即可。

關鍵字進去，一份「標題＋網址＋摘要」的清單出來。

**這個 skill 不會給你答案，只會給你線索。** 摘要是搜尋引擎寫的，不是原文。
要根據內容回答問題，**一定要再用 fetch 把那一頁讀進來**。

> 路徑說明：description 裡寫死 `/workspace/...`，那是 `SANDBOX=docker:*` 時容器看到的位置。
> 若改成 `SANDBOX=host`，路徑會變成 host 上的 `$STATE_DIR/channels/skills/`，description 要一起改。

## 用法

```bash
sh {baseDir}/search.sh <關鍵字>
```

範例：

```bash
sh {baseDir}/search.sh 台北 2026 垃圾車 時間表
```

關鍵字不用引號也可以，整串參數會被當成一個查詢。

## 輸出

```
搜尋：台北 垃圾車 時間表（brave，最多 5 筆）

1. 臺北市垃圾清運時間查詢
   https://example.gov.tw/trash
   提供各行政區垃圾車路線與時間…

以上只是標題與摘要。要知道某一筆實際寫什麼，用 fetch 讀那個網址。
```

## 正確的用法是兩步

1. `search.sh <關鍵字>` → 拿到候選網址
2. 挑**一個**最相關的 → `fetch.sh <url>` → 讀實際內容
3. 回答時附上那個網址

**不要一次 fetch 五個結果。** 每一頁最多 12000 bytes，五頁就把 context 吃光了。

## 限制

- **一次最多 5 筆**，摘要截到 200 字。這是 context 預算，不是可調參數。
- **後端目前是自架的 SearXNG**，不需要 API key。若使用者改成 brave／tavily 才需要，
  沒設定時會告訴你——那不是你能自己解決的事，直接把訊息轉達給使用者，
  **不要試圖繞過或自己去爬網頁**。
- SearXNG 是代你去問其他搜尋引擎的，**問太快會被上游擋**。
  同一個問題不要反覆搜；一次查不到就換關鍵字，不要連打。

## 失敗時會看到什麼

| 訊息 | 意思 | 你該做什麼 |
| --- | --- | --- |
| `✗ 連不上自架的 SearXNG` | 搜尋服務沒起來 | 轉達給使用者，請他們檢查 `bin/searxng.sh status` |
| `✗ SearXNG 拒絕了 JSON 請求` | 設定問題 | 轉達給使用者，這是設定檔要改，不是你的問題 |
| `✗ 還沒設定搜尋用的 API key` | 使用者選了 brave／tavily 但沒填 | 轉達給使用者，本次回答改用你已知的資訊，並說明你沒查證 |
| `✗ API key 被拒絕` | key 填錯或失效 | 轉達給使用者 |
| `✗ 超過用量上限` | 這個月配額用完 | 告訴使用者，今天不要再搜 |
| `（查無結果：...）` | 關鍵字太窄 | 換更短、更通用的關鍵字再試**一次**，還是沒有就回報 |

## 回答的時候

**答案來自網路就要附上來源網址**，並且說明那是你查到的、不是你原本就知道的。
