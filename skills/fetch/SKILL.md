# fetch

> **2026-09-15：`fetch` 已經是內建工具了。**
> 這份文件保留下來當實作說明與備援（bash 路徑仍然可用），
> 但正常情況下直接呼叫 `fetch` 工具即可。

把網址變成純文字。**只有在你需要知道某一頁實際寫了什麼的時候才用它**——
你已經知道答案的事不要再抓一次網頁。

> 路徑說明：description 裡寫死 `/workspace/...`，那是 `SANDBOX=docker:*` 時容器看到的位置。
> 若改成 `SANDBOX=host`，路徑會變成 host 上的 `$STATE_DIR/channels/skills/`，description 要一起改。

## 用法

```bash
sh {baseDir}/fetch.sh <url>
```

範例：

```bash
sh {baseDir}/fetch.sh https://example.com
```

## 輸出

前兩行是來源與上限說明，空一行之後才是內容：

```
來源：https://example.com
（純文字擷取，上限 12000 bytes）

Example Domain
This domain is for use in documentation examples...
```

## 你必須知道的限制

- **上限 12000 bytes**（約 12000 個英數字、或 4000 個中文字）。超過會被截斷，
  結尾會出現 `⚠ 內容已截斷`。**這時候不要重抓同一頁**——重抓結果一樣。
  要更後面的內容，換一個更精確的網址。
- **只處理網頁與純文字。** PDF、圖片、影音會直接失敗並告訴你 content-type。
- **不會登入。** 需要帳號才看得到的頁面只會拿到登入頁。
- **不跟隨無限轉址**，逾時 20 秒。

## 失敗時會看到什麼

| 訊息 | 意思 | 你該做什麼 |
| --- | --- | --- |
| `✗ HTTP 404：<url>` | 網址不存在 | 別再試同一個網址，改用 search 找正確的 |
| `✗ 連不上：<url>` | DNS 或連線失敗 | 確認網址拼字；再一次仍失敗就回報使用者 |
| `✗ 不是文字內容` | PDF／圖片／影音 | 告訴使用者這個檔案這裡讀不了 |
| `✗ 抓到的內容是空的` | 頁面靠 JavaScript 產生 | 告訴使用者這頁需要瀏覽器才看得到 |

## 回答的時候

**一定要附上來源網址。** 使用者要能自己去核對你說的話是不是真的在那一頁上。
